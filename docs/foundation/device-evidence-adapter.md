# F05 physical probe evidence adapter

`tools/backends/device.py` implements only the registered operation:

```text
qualify --scope xr-probe --models quest3,quest3s --native-cases evidence/runs/F05/<run>/<attempt>/backend-cases.json
```

The runner invokes it for the existing `check-f05` command. It does not discover,
connect to, install on, or operate devices. This source closes an adapter gap;
no actual inlet is supplied and F05 remains unaccepted. Five worlds and all 25
missions remain in scope. This foundation probe establishes neither game
qualification nor comfort, performance, human acceptance, or release readiness.

## Future actual input

The fixed inlet is `evidence/toolchain/device/probe-input.json`. It must be an
object containing `schema_version: 1`,
`record_type: "resq-reviewed-xr-probe-input"`, `probe`, and `provenance_reviews`.
`probe` is the complete existing supplemental
`resq-xr-probe-observations` packet documented in
[xr-setup.md](xr-setup.md#f05-actual-observations-and-supplemental-validator).
Its identity, APK/native report, source/content snapshots, toolchain lock,
both physical sessions and all 20 observations must pass
`foundation_probe.validate_probe` unchanged.

The adapter additionally verifies the exact current accepted F04 result path
and SHA against `automation/task_state.json`, runs the independent root result
validator with historical F04 gate verification, and binds the exact F04
source/content/toolchain references. F05 admission independently requires its
current `quest_devices` gate; refreshing a historical setup/storage gate does not
invalidate a completed accepted F04 build. The three
project version/package manifest/package lock bytes must match the corresponding
files in F04's source snapshot. The accepted F04 output binding for
`automation/toolchain.lock.json` must bind the same toolchain bytes. Pending,
stale, failed, invented, and structurally incomplete F04 records cannot qualify.

`provenance_reviews` contains exactly two artifact references, one per headset
model. Each is a relative owned regular file with `path`, `sha256`, and positive
integer `size_bytes`. No symlink, traversal, or outside-workspace input is allowed.
The referenced JSON record must contain:

| Field | Required value |
|---|---|
| `schema_version` | Integer `1` |
| `record_type` | `resq-physical-probe-provenance-review` |
| `decision` | `accepted_actual_provenance` |
| `review_basis` | `direct_inspection_of_original_records` |
| `reviewer_kind` | `human` or `authorized_independent_reviewer` |
| `reviewer_alias` | Explicit nonempty alias different from the session's observer |
| `reviewed_utc` | UTC timestamp at or after session completion |
| `review_notes` | Specific nonempty original-record inspection notes |
| `probe_sha256` | Canonical SHA-256 of the entire supplemental `probe` object |
| `candidate_sha256` | Exact supplemental candidate identity digest |
| `f04_result` | Exact supplemental F04 artifact reference |
| `model`, `session_id`, `device_alias`, `os_build`, `started_utc`, `ended_utc` | Exact matching session values |
| `reviewed_artifacts` | Object with exact session references for `device_authorization`, `consent`, `capture`, `runtime_log`, and `device_identity` |
| `checks` | The exact boolean check set below, all explicitly `true` |

Canonical hashes use Python UTF-8
`json.dumps(value, sort_keys=True, separators=(",", ":"))`, then SHA-256. No
review record is generated by the adapter. The review is an explicit attestation
of direct inspection, not a human signoff or an independent cryptographic proof
that the supplied statements are true. Reviewers must describe their actual
inspection; do not create records from intended actions or fixture data.

The exact review checks are `actual_physical_device`, `standalone_apk`,
`capture_inspected`, `runtime_log_inspected`, `device_identity_inspected`,
`authorization_scope_confirmed`, `consent_scope_confirmed`,
`all_observations_correlated`, and `exact_package_lock_after_probe`.
They refer to the completed session and original retained records. Account access,
credits, discovered headsets, or an otherwise valid JSON record cannot substitute
for authorization, consent, actual sessions, or inspection.

## Retention and frozen assertions

After complete validation, the adapter copies the inlet, reviewed provenance,
all supplemental artifacts and nested source/content inputs, plus recursively
referenced accepted F04 result/report evidence and the exact case contract, to
`evidence/runs/F05/<run>/<attempt>/probe-inputs/`. Each original path, retained
path, SHA and byte count is recorded in `probe-retention.json`. Original bytes are
checked before copying and all retained bytes are rechecked before native success.
Existing files are never overwritten; partial failed retention is preserved.

The four exact frozen F05 assertion cases each include both model sessions,
all observations, retained device/authorization/consent/log/capture references,
review references and package/toolchain identity. Each case has a valid physical
proof index. Exactly two `physical_device` proof records use the frozen root
schema, and their capture paths point to the per-attempt retained copies.
`candidate_identity` equals the entire current F04 result identity. The runner
independently rechecks this binding before using the tested APK identity.

Only after these checks does the adapter write the expected artifact
`evidence/toolchain/device/probe.json` and native `backend-cases.json`.
The expected artifact includes the complete supplemental packet and reviewed
structural-validation summary. Both mark `accepted_task: false`. A conflicting
existing output or native case history fails; an identical summary can be
reverified into a fresh owned attempt. Neither file changes task state or accepts
F05. Root verification and independent review of the underlying physical evidence
remain mandatory before the coordinator's acceptance path.

Missing actual inlet or unsupported operation exits `75`. Malformed or incomplete
actual records, missing capture/consent bytes, stale identities, changed evidence,
invalid review records and conflicting history exit `1`. No simulator, Link,
Editor, synthetic fixture, count-derived case, or unreviewed packet is admitted.

## Isolated validation

`tools/test_device_backend.py` contains temporary synthetic security fixtures.
Only the accepted-F04 root validator is mocked because fixture F04 records are
explicitly incapable of root acceptance; the real supplemental validator runs.
The tests exercise operation/path boundaries, missing and malformed input,
current F04/candidate/review/session identity, missing consent/capture,
simulator rejection, retention tampering, exact frozen proof shapes and both
sessions per assertion. They write only temporary directories. They are automated
adapter behavior evidence and never physical-device evidence.

The coordinator schedules and records their actual execution under the shared
single-heavy-job rule. This document records implementation, not a passing test
run or an observed physical qualification.
